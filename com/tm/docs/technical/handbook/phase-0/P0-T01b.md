# Handbook — P0-T01b: `com/tm/app` pnpm workspace (`pnpm-workspace.yaml`, `package.json` gốc, script `dev`/`build`/`test` chạy theo filter)

## Pin phiên bản pnpm bằng `packageManager`, không cần corepack
- **Chủ đề**: `node/pnpm`, `node/tooling`
- **Bối cảnh**: Máy dev có pnpm toàn cục 12.6.0, không có lệnh `corepack`; dự án chốt `pnpm@11.18.0` và Node ≥ 22. CI và máy dev phải chạy đúng một bản pnpm, nếu không lockfile sẽ bị viết lại khác nhau.
- **Cách làm & lý do**: `package.json` gốc khai báo `"packageManager": "pnpm@11.18.0"` và `"engines": {"node": ">=22"}`. Từ pnpm 9.7, pnpm tự đọc `packageManager` và chuyển sang đúng bản đó (`manage-package-manager-versions`), nên `pnpm -v` trong `com/tm/app` in `11.18.0` dù bản toàn cục là 12.6.0. Không cần bật corepack. `pnpm-workspace.yaml` chỉ có glob `apps/*`, `packages/*` (không gồm `api/` vì đó là file OpenAPI, không phải package). Package gốc đặt tên `snaptix-app` và `private: true` để loại được bằng filter và không lỡ publish.
- **Bẫy / lưu ý**: Workspace chưa có package nào thì lockfile chỉ có `importers: .: {}`. Vẫn commit nó để `pnpm install --frozen-lockfile` chạy được ngay từ đầu. `node_modules/` đã bị bỏ qua bởi `.gitignore` gốc, nhưng `git check-ignore com/tm/app/node_modules` chỉ trả 0 **sau khi** thư mục tồn tại, vì pattern có `/` cuối chỉ khớp thư mục có thật.
- **Code**: [app/package.json#L1-L16 — packageManager, engines, scripts](../../../../app/package.json#L1-L16), [app/pnpm-workspace.yaml](../../../../app/pnpm-workspace.yaml)
- **Tham khảo**: [pnpm — package.json `packageManager`](https://pnpm.io/package_json#packagemanager), [pnpm-workspace.yaml](https://pnpm.io/pnpm-workspace_yaml)

## Script gốc `pnpm --recursive --if-present`, `dev` thêm `--parallel`
- **Chủ đề**: `node/pnpm`
- **Bối cảnh**: Script gốc `build`/`test`/`lint`/`typecheck`/`dev` phải chạy qua mọi package. Package không có script thì bỏ qua, và workspace rỗng (trạng thái hiện tại) phải exit 0.
- **Cách làm & lý do**:
  - `pnpm --recursive --if-present <script>`: chạy theo **thứ tự topo**, tức package được phụ thuộc chạy trước (fixture: `build-a` trước `build-b` vì tc-b phụ thuộc tc-a). `--if-present` bỏ qua package thiếu script. `-r` **không** tự gọi lại package gốc, nên không đệ quy vô hạn.
  - `dev` thêm `--parallel`: dev server không bao giờ kết thúc, nếu chờ topo thì app phụ thuộc sẽ không bao giờ khởi động. Kiểm bằng fixture: `dev-b start` in trước `dev-a end`.
  - Lỗi của một package được truyền ra exit code của lệnh gốc (`exit 3` ở tc-c → `pnpm test` exit 3, `ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL`). CI (P0-AT05) dựa vào điều này.
- **Bẫy / lưu ý**:
  - Workspace rỗng in `No projects matched the filters` và vẫn exit 0.
  - Filter không khớp package nào cũng exit 0 (`pnpm --filter khong-ton-tai build`). Muốn fail thì thêm `--fail-if-no-match` (exit 1). P0-T04 chọn cờ tuỳ ý muốn: PR không đụng package nào thì **không** nên fail.
  - Package không có `node_modules` (không có dependency) sẽ làm pnpm in `WARN Local package.json exists, but node_modules missing`. Cảnh báo này vô hại.
- **Code**: [app/package.json#L9-L15 — scripts](../../../../app/package.json#L9-L15)
- **Tham khảo**: [pnpm run — `--recursive`, `--parallel`, `--if-present`](https://pnpm.io/cli/run)

## `pnpm ... lint test build` chỉ chạy `lint`: dùng `run '/regex/'`
- **Chủ đề**: `node/pnpm`, `ci`
- **Bối cảnh**: Docs (CLAUDE.md bước 4, `project-structure.md` bảng CI, dòng P0-T04) ghi lệnh `pnpm --filter "...[origin/main]" lint test build`. Chạy thử trên fixture thì pnpm chỉ chạy `lint` với **đối số** `test build` (`echo lint-a test build`) và exit 0, nên lỗi bị che. Root còn bị chọn (vì `package.json` gốc đổi) và tự chạy đệ quy lại (dòng `. lint$ pnpm --recursive --if-present lint test build`).
- **Cách làm & lý do**: Lệnh đúng là `pnpm --filter "...[origin/main]" --filter '!snaptix-app' --if-present run '/^(lint|test|build)$/'`.
  - `run '/regex/'` chạy mọi script có tên khớp regex.
  - `--filter '!snaptix-app'` loại package gốc.
  - `--if-present` tránh lỗi `ERR_PNPM_RECURSIVE_RUN_NO_SCRIPT` khi package được chọn không có script nào khớp (đã thử: thiếu cờ này thì exit 1).
  - `...[ref]` chọn package có file đổi so với `ref` **cộng các dependents** của nó. File chưa được track không tính: tc-c chưa `git add` thì không được chọn.
- **Bẫy / lưu ý**:
  - Với regex, các script khớp chạy **đồng thời** trong cùng một package: output cho thấy `test`, `build`, `lint` của tc-a cùng start. Giữa các package vẫn theo thứ tự topo. Nếu sau này cần tuần tự (vd build xong mới test), gọi 3 lệnh lần lượt thay vì regex.
  - CLAUDE.md và dòng P0-T04 chưa sửa (ngoài phạm vi). Đề xuất đã ghi ở `planning/execute-all-notes.md`.
- **Code**: [project-structure.md — mục CI](../../project-structure.md#ci), [local-setup.md — Build & kiểm thử](../../local-setup.md#build--kiểm-thử)
- **Tham khảo**: [pnpm filtering — `...[<since>]`, `!`](https://pnpm.io/filtering), [pnpm run — regex](https://pnpm.io/cli/run#running-multiple-scripts)

## pnpm 11 tự cài lại deps trước khi chạy script
- **Chủ đề**: `node/pnpm`, `ci`
- **Bối cảnh**: Sau khi sửa `package.json` của fixture, `pnpm install --frozen-lockfile` fail đúng như mong đợi (`ERR_PNPM_OUTDATED_LOCKFILE`, exit 1). Nhưng lệnh kế tiếp `pnpm --filter tc-b build` lại in `Already up to date` rồi chạy script, và **`pnpm-lock.yaml` đã bị viết lại** (thêm importer `tc-c`).
- **Cách làm & lý do**: pnpm 11 kiểm tra trạng thái deps trước mỗi lần `run` (setting `verifyDepsBeforeRun`; ở đây `pnpm config get` in `undefined`, tức là dùng mặc định, và hành vi quan sát được là tự install). Thấy `package.json` lệch với `node_modules` thì nó tự `install`, không dùng frozen. Vì vậy chỉ `pnpm install --frozen-lockfile` mới là chốt chặn lockfile. CI (P0-T04) phải chạy lệnh này **trước** mọi script, và nên thêm `git diff --exit-code pnpm-lock.yaml` sau khi chạy script.
- **Bẫy / lưu ý**:
  - Khi dọn fixture phải `pnpm install` lại rồi so lockfile với bản sao lưu (`cmp`). Ở task này lockfile khôi phục đúng từng byte.
  - Dòng `Already up to date` in ra lúc chạy script là của lần install tự động này, không phải output của script.
- **Tham khảo**: [pnpm settings — verifyDepsBeforeRun](https://pnpm.io/settings#verifydepsbeforerun)
