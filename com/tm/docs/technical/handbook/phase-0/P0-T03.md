# Handbook — P0-T03: Cấu hình goose, thư mục `com/tm/server/db/core/migrations`, `com/tm/server/db/analytics/migrations`, migration rỗng đầu tiên

## Pin goose bằng `go install ...@v3.28.0`, chạy trên host
- **Chủ đề**: `pg/migration`, `go/tooling`
- **Bối cảnh**: Docs chỉ ghi "Công cụ: `goose`", máy dev chưa có CLI. Các task trước đều pin phiên bản công cụ (Bazel, pnpm, image). Docker Desktop treo khi bind mount repo trong `~/Documents` (P0-T02), nên không chạy goose trong container.
- **Cách làm & lý do**:
  - `go install github.com/pressly/goose/v3/cmd/goose@v3.28.0`, binary nằm ở `$(go env GOPATH)/bin`. Ghi vào `local-setup.md` kèm `goose -version` để kiểm.
  - Phương án `tool` directive trong `go.mod` (`go tool goose`) bị loại: kéo cả driver của goose (pgx, mysql, sqlite, clickhouse...) vào `go.mod`/`go.sum` của server, phải `bazel mod tidy` và Bazel/Gazelle thấy thêm hàng chục module chỉ để có một CLI. Giữ `go.mod` sạch thì build Bazel không đổi.
  - goose chạy trên host, kết nối PG qua cổng publish 5432/5433. Không cần `?sslmode=disable`: pgx mặc định `prefer`, thử TLS rồi fallback plaintext.
- **Bẫy / lưu ý**:
  - Máy dev chưa có `$(go env GOPATH)/bin` trong `PATH`; phải thêm, nếu không `goose` "command not found" dù đã cài.
  - `go install` không ghi gì vào repo, nên CI (P0-T04) và Makefile (P0-T05) phải tự cài đúng `@v3.28.0`. Không dùng `@latest`.
- **Code**: [local-setup.md — Yêu cầu, bước 2](../../local-setup.md)
- **Tham khảo**: [pressly/goose](https://github.com/pressly/goose)

## Migration rỗng đầu tiên: SQL, đánh số tuần tự, annotation Up/Down
- **Chủ đề**: `pg/migration`
- **Bối cảnh**: Cần xác nhận đường chạy migration cho hai PG riêng (core, analytics) mà chưa có schema nghiệp vụ.
- **Cách làm & lý do**:
  - Mỗi thư mục một file `00001_init.sql` gồm `-- +goose Up` / `SELECT 1;` / `-- +goose Down` / `SELECT 1;`. Không tạo object nào; `up` chỉ làm goose tạo `public.goose_db_version` (dòng `0|t` rồi `1|t`).
  - Đánh số **tuần tự** (`goose -s create`) thay vì timestamp (mặc định của `goose create`): dự án một người, không có nhánh song song tạo migration cùng lúc, số nhỏ dễ đọc trong `version`/`status`. Hai thư mục dùng chung kiểu.
  - SQL, không Go migration: CLI `goose` chuẩn chỉ chạy được SQL; migration Go cần build binary riêng.
  - Gazelle không sinh `BUILD.bazel` trong `db/` vì không có file `.go`; `bazel test //...` không đổi.
- **Bẫy / lưu ý**:
  - File thiếu annotation: goose vẫn áp dụng các migration hợp lệ **đứng trước** rồi mới lỗi `failed to parse SQL migration file` (exit 1). Không có "kiểm tra hết rồi mới chạy".
  - SQL lỗi trong migration: chạy trong transaction nên version không được ghi, bảng không tồn tại (exit 1, `syntax error`).
  - `down` xoá dòng version (bảng còn `0|t`), không đánh dấu `is_applied=false`.
  - `up` lần đầu in `successfully migrated database to version: N`; chỉ khi không còn gì để chạy mới in `no migrations to run. current version: N`.
  - `goose status` trên DB mới **tạo** bảng `goose_db_version` (lệnh "đọc" nhưng có ghi).
  - Unit test (bước 3) không áp dụng: task không có code Go; hành vi migration được kiểm bằng test case chạy goose thật với PG trong compose (TC06–TC17). Integration test testcontainers là P0-T16.
