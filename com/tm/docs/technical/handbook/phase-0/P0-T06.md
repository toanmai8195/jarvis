# Handbook — P0-T06: Dashboard Grafana cơ bản: RED metrics cho mỗi service

## Provisioning dashboard từ file, bake vào image
- **Chủ đề**: `observability/grafana`, `docker`
- **Bối cảnh**: dashboard RED phải có sẵn khi `make up`, và phải sống qua `down -v`. Không được bind mount repo vào container, vì Docker Desktop treo khi mount thư mục trong `~/Documents` (P0-T02).
- **Cách làm & lý do**:
  - JSON dashboard nằm ở `deploy/observability/grafana/dashboards/red.json`. Provider `type: file` trỏ `options.path: /etc/grafana/dashboards`. Dockerfile `COPY dashboards /etc/grafana/dashboards`. Dashboard là một phần của image, nên có sẵn sau `down -v` (TC18). Sửa JSON rồi `up -d --wait` thì compose build lại image (`pull_policy: build`) và Grafana nhận bản mới (TC19).
  - `uid` cố định (`snaptix-red`) để link `/d/snaptix-red` và API không đổi giữa các lần dựng. `id: null`: Grafana tự cấp id.
  - Datasource viết thẳng `{"type":"prometheus","uid":"prometheus"}`, khớp uid cố định trong `datasources.yaml`. Không dùng dạng export `__inputs` + `${DS_PROMETHEUS}`: dạng đó dành cho import tay, provisioning không thay placeholder nên panel sẽ lỗi "datasource not found".
- **Bẫy / lưu ý**:
  - Grafana chỉ log lỗi provisioning (JSON hỏng, sai `path`) ở `logger=provisioning.dashboard`, container vẫn healthy. Muốn bắt lỗi thì lọc đúng logger này. `logger=migrator` của 13.2.2 có sẵn vài dòng `level=warn` về index, không liên quan tới dashboard.
  - Có script kiểm tĩnh `check-dashboards.sh` (uid, datasource, biến, họ metric, `job=~"$service"`) để phát hiện lỗi trước khi dựng stack.
- **Code**: [grafana/Dockerfile#L12-L13 — COPY provisioning, dashboards](../../../../../../deploy/observability/grafana/Dockerfile#L12-L13), [provisioning/dashboards/dashboards.yaml — provider `snaptix`](../../../../../../deploy/observability/grafana/provisioning/dashboards/dashboards.yaml), [check-dashboards.sh#L28-L61 — check_dashboard, check_provider](../../../../../../deploy/observability/grafana/check-dashboards.sh#L28-L61)
- **Tham khảo**: [Grafana — Provision dashboards](https://grafana.com/docs/grafana/latest/administration/provisioning/#dashboards)

## `disableDeletion` + `allowUiUpdates: false`: dashboard là code
- **Chủ đề**: `observability/grafana`
- **Bối cảnh**: Grafana ẩn danh có quyền Admin (local-setup), nên ai cũng sửa được dashboard trên UI. Nếu bản trên UI lệch file trong repo thì lần dựng sau thay đổi đó bị mất.
- **Cách làm & lý do**: provider đặt `disableDeletion: true` và `allowUiUpdates: false`. Grafana từ chối lưu và xoá: `POST /api/dashboards/db` trả `400 Cannot save provisioned dashboard`, `DELETE` trả `400 provisioned dashboard cannot be deleted` (TC07). Muốn sửa thì sửa JSON và commit. UI vẫn cho "Make editable" để thử, rồi export JSON dán vào file.
- **Bẫy / lưu ý**: nếu `allowUiUpdates: true`, bản lưu từ UI sẽ nằm trong DB Grafana (volume), và provisioning chỉ ghi đè khi file đổi. Kết quả là trạng thái dashboard phụ thuộc cả file lẫn volume, khó biết bản nào đang chạy.
- **Code**: [provisioning/dashboards/dashboards.yaml — disableDeletion, allowUiUpdates](../../../../../../deploy/observability/grafana/provisioning/dashboards/dashboards.yaml)
- **Tham khảo**: [Grafana — Making changes to a provisioned dashboard](https://grafana.com/docs/grafana/latest/administration/provisioning/#make-changes-to-a-provisioned-dashboard)

## Label service là `job` khi metric vào bằng OTLP push
- **Chủ đề**: `observability/prometheus`, `otel/semconv`
- **Bối cảnh**: dashboard cần biến chọn service, trong khi chưa có service thật (core/bff từ P0-T07+). Metric vào Prometheus 3.15 bằng OTLP push qua collector.
- **Cách làm & lý do**:
  - Metric theo OTel HTTP semconv stable: `http.server.request.duration` (giây). Prometheus dịch thành `http_server_request_duration_seconds_{bucket,count,sum}`, attribute thành label `http_route`, `http_response_status_code`...
  - Khi nhận OTLP, Prometheus đặt `job` = `<service.namespace>/<service.name>` (vd `snaptix/p0t06-alpha`). `service_name` chỉ có trên `target_info`, không có trên series metric. Vì vậy biến `service` là `label_values(http_server_request_duration_seconds_count, job)`: chỉ liệt kê job **có metric RED**, nên không lẫn `prometheus`/`otel-collector`. Mọi query lọc `job=~"$service"`, với `multi` + `includeAll`.
  - Test bằng generator Python đẩy histogram cumulative qua OTLP HTTP `:4318` cho 2 service giả, rồi so số tính tay (rate 11/4 req/s, p95 0.3625 s...) trong ±5 %.
- **Bẫy / lưu ý**: khi P0-T07 thêm scrape `/metrics`, `job` là tên scrape job (vd `core`), khác dạng `snaptix/core` của OTLP. Biến vẫn chạy vì lấy theo label thật, nhưng hai nguồn của cùng một service sẽ thành hai giá trị. Nên chọn một nguồn cho mỗi service.
- **Code**: [red.json#L28-L51 — templating `service`](../../../../../../deploy/observability/grafana/dashboards/red.json#L28-L51), [red.json#L80-L105 — Request rate theo service/route](../../../../../../deploy/observability/grafana/dashboards/red.json#L80-L105)
- **Tham khảo**: [OTel semconv — HTTP metrics](https://opentelemetry.io/docs/specs/semconv/http/http-metrics/), [Prometheus — OTLP receiver](https://prometheus.io/docs/guides/opentelemetry/)

## Error rate: `(5xx or total * 0) / total` để service không lỗi ra 0
- **Chủ đề**: `observability/promql`
- **Bối cảnh**: error rate = request 5xx / tổng request. Service chưa có 5xx (beta) không có series 5xx nào, nên `sum(rate(5xx)) / sum(rate(all))` trả **rỗng** cho service đó. Panel hiện thiếu service, và không phân biệt được "không lỗi" với "không có dữ liệu".
- **Cách làm & lý do**: tử số là `sum by (job)(rate(..{code=~"5.."})) or sum by (job)(rate(..)) * 0`. `or` lấy vế trái nếu có, không thì lấy vế phải: cùng label `job`, giá trị 0. Kết quả: alpha 0.0908 (1/11), beta `0` có series. Chỉ tính `5..`: 4xx là lỗi phía client, tính vào sẽ ra 0.1818 với alpha.
- **Bẫy / lưu ý**: `by (job)` phải giống nhau ở cả hai vế của `or` và ở mẫu số, nếu không phép chia khớp label sẽ ra rỗng. Service không có request thì vẫn `No data` (không chia 0/0 ra NaN), đúng ý nghĩa.
- **Code**: [red.json#L148 — Error rate (5xx) expr](../../../../../../deploy/observability/grafana/dashboards/red.json#L148)
- **Tham khảo**: [Prometheus — Logical/set binary operators (`or`)](https://prometheus.io/docs/prometheus/latest/querying/operators/#logical-set-binary-operators)

## Grafana 13 tải plugin datasource ngầm sau health: cài sẵn khi build
- **Chủ đề**: `observability/grafana`, `docker/healthcheck`
- **Bối cảnh**: ngay sau `up -d --wait` (Grafana đã healthy), mọi query của dashboard trả 404 `plugin.notRegistered` trong vài giây rồi mới chạy. Test "stack mới, chưa có metric" ra `ERROR` thay vì `NO DATA`.
- **Cách làm & lý do**: Grafana 13 tách plugin `prometheus`/`tempo` khỏi core. Mặc định chúng được background installer tải từ Internet **sau** khi `/api/health` đã OK. Dockerfile chạy `grafana cli plugins install prometheus 13.2.1 && ... tempo 13.2.2` lúc build. Healthy nghĩa là dùng được ngay, và lúc chạy không cần mạng cho hai plugin này.
- **Bẫy / lưu ý**: khi nâng bản Grafana thì phải nâng hai bản plugin pin theo. Healthcheck `/api/health` không phản ánh plugin đã sẵn sàng. Các plugin khác vẫn được tải ngầm (ghi ở `execute-all-notes.md`).
- **Code**: [grafana/Dockerfile#L5-L10 — RUN grafana cli plugins install](../../../../../../deploy/observability/grafana/Dockerfile#L5-L10)
- **Tham khảo**: [Grafana — Plugin preinstall (`GF_PLUGINS_PREINSTALL`)](https://grafana.com/docs/grafana/latest/setup-grafana/configure-grafana/#preinstall)
