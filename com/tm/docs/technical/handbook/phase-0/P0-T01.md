# Handbook — P0-T01: Khởi tạo cấu trúc `com/tm/{server,app,docs}`, `deploy/`, `loadtest/` theo project-structure

## Git không track thư mục rỗng: `.gitkeep` hoặc README
- **Chủ đề**: `git`
- **Bối cảnh**: Khung `com/tm/server/{api,pkg,services}`, `com/tm/app/{api,apps,packages}`, `loadtest/results/` chưa có code, nhưng phải tồn tại sau khi clone để task sau và script kiểm tra dựa vào.
- **Cách làm & lý do**: Thư mục sẽ sớm có code → `.gitkeep` rỗng (xoá được khi có file thật). Thư mục cấp gốc cần giải thích mục đích (`deploy/`, `loadtest/`) → `README.md` ngắn, vừa giữ thư mục vừa là tài liệu.
- **Bẫy / lưu ý**: `git ls-files <dir>` chỉ thấy file trong index — kiểm tra "thư mục đã được track" trước khi commit phải `git add` trước, nếu không ra kết quả sai (fail giả ở kiểm tra "có file", pass giả ở kiểm tra "không có rác"). `git check-ignore -q` là cách kiểm `.gitignore` đúng/sai mà không cần tạo file thật: `loadtest/*.tmp.json` và `.env` bị ignore, còn `loadtest/results/*.json`, `.env.example` (nhờ `!.env.example`) thì không.

## Script kiểm tra cấu trúc nhận ROOT làm tham số
- **Chủ đề**: `bash`, `testing`
- **Bối cảnh**: Cần một luật tự động cho "đủ thư mục bắt buộc" và "không có thư mục kiểu Java / chung chung" (`service`, `repository`, `utils`, `common`, `shared`...) để CI (P0-T04) và Makefile (P0-T05) gọi lại; đồng thời phải test được ca lỗi mà không sửa repo thật.
- **Cách làm & lý do**: `check-structure.sh [ROOT]` — ROOT mặc định là `git rev-parse --show-toplevel`, không phải git repo thì dùng `pwd`. Nhờ ROOT là tham số, test dựng cây giả trong `mktemp -d` và chạy script trên đó (không cần `git worktree`, và worktree cũng không chứa file chưa commit). Script gom **mọi** lỗi rồi mới exit 1 (không dừng ở lỗi đầu) để một lần chạy thấy hết; lỗi in ra stderr theo dạng cố định `MISSING dir: <path>` / `FORBIDDEN dir: <path>` để test grep được; exit 2 riêng cho ROOT sai để phân biệt với "cấu trúc sai".
- **Bẫy / lưu ý**:
  - `find -name service` so khớp nguyên tên nên `services/` hợp lệ không bị bắt — có ca test riêng `services_plural_ok` để khoá hành vi này.
  - Tên cấm có thể xuất hiện trong thư mục không do ta đặt (`node_modules/*/utils`, `bazel-out/...`) → `find ... \( -name node_modules -o -name 'bazel-*' -o -name dist -o -name .git \) -prune -o ...`; thiếu `-prune` thì sau P0-T01b script sẽ fail ngay.
  - macOS dùng `/bin/bash` 3.2: tránh `mapfile`, `declare -A`; mảng rỗng + `set -u` cần cẩn thận — build biểu thức `-name a -o -name b` bằng mảng và chỉ thêm `-o` khi mảng đã có phần tử.
  - Test ca "không truyền ROOT" chạy trong thư mục tạm: đặt `GIT_CEILING_DIRECTORIES` để `git rev-parse` không leo lên repo cha ngoài ý muốn.
  - `shellcheck` SC2015: `A && B || C` không phải if-then-else — đổi sang `if ...; then ...; else ...; fi`.
