## bzlmod: một `go.mod` làm nguồn sự thật cho cả `go` và Bazel
- **Chủ đề**: `bazel`, `bazel/bzlmod`, `go/modules`
- **Bối cảnh**: Challenge G14 đòi code build được bằng cả `go` (vòng dev nhanh, gopls) lẫn Bazel (CI, image). Nếu phiên bản Go hoặc dependency khai báo hai nơi, sớm muộn sẽ lệch.
- **Cách làm & lý do**: `go_sdk.from_file(go_mod = "//:go.mod")` lấy phiên bản SDK từ dòng `go 1.27.1`; `go_deps.from_file(go_mod = "//:go.mod")` lấy dependency. Thêm thư viện: `go get` → `bazel mod tidy` (sửa `use_repo`) → `bazel run //:gazelle`. `.bazelversion` = `8.7.0` (Bazelisk tự tải; rules_oci chưa hỗ trợ Bazel 9 — máy dev có Bazel 9.2 mặc định, không pin là vỡ). Không có `WORKSPACE`; `MODULE.bazel.lock` được commit, kiểm bằng `git diff --exit-code` sau build và sau `bazel mod tidy`.
- **Bẫy / lưu ý**:
  - Module chưa có dependency ngoài → không có `go.sum`; `go_deps.from_file` vẫn chạy được.
  - `go build ./...` khi pattern khớp **đúng một** package `main` sẽ ghi binary ra cwd (ở đây là `com/tm/server/smoke`) — suýt bị `git add`. Đã thêm vào `.gitignore`; khi có nhiều package thì `go build ./...` tự bỏ output.
- **Code**: [MODULE.bazel#L9-L22 — bazel_dep, go_sdk, go_deps](../../../../server/MODULE.bazel#L9-L22), [go.mod](../../../../server/go.mod), [.gitignore — `/com/tm/server/smoke`](../../../../../../.gitignore)
- **Tham khảo**: [rules_go — bzlmod](https://github.com/bazel-contrib/rules_go/blob/master/docs/go/core/bzlmod.md), [Bazel lockfile](https://bazel.build/external/lockfile)

## Gazelle: `go_naming_convention import` và `map_kind go_binary`
- **Chủ đề**: `bazel/gazelle`
- **Bối cảnh**: Không viết BUILD tay; mọi `go_binary` phải thành binary + image mà người viết service không cần nhớ.
- **Cách làm & lý do**: Directive trong `BUILD.bazel` gốc: `prefix` = module path, `go_naming_convention import` → tên target theo thư mục (`smoke_lib`, `smoke_test`, `gazellecheck`) thay vì legacy `go_default_library`. `map_kind go_binary com_tm_go_image //tools/rules:com_tm_container.bzl` → Gazelle sinh `com_tm_go_image(name = "smoke", embed = [":smoke_lib"])` kèm `load(...)`, và lần chạy sau vẫn nhận ra đó là `go_binary` đã map (idempotent: `bazel run //:gazelle -- -mode=diff` exit 0).
- **Bẫy / lưu ý**: Package `main` sinh `<dir>_lib` + binary tên `<dir>`; package thường sinh `go_library` tên `<dir>` với `visibility` public — cần siết ở các task có service (P0-AT13). Kiểm "đúng như Gazelle sinh" bằng `-mode=diff`, không bằng mắt.
- **Code**: [BUILD.bazel#L1-L6 — directive + gazelle](../../../../server/BUILD.bazel#L1-L6), [tools/smoke/BUILD.bazel — output Gazelle](../../../../server/tools/smoke/BUILD.bazel)
- **Tham khảo**: [Gazelle directives](https://github.com/bazel-contrib/bazel-gazelle#directives)

## Macro `com_tm_go_image`: binary + layer + OCI image distroless
- **Chủ đề**: `bazel/rules_oci`, `bazel/macro`, `docker`
- **Bối cảnh**: Mỗi binary Go cần image nhỏ, không shell, build tái lập, không Dockerfile.
- **Cách làm & lý do**: Macro sinh `<name>` (`go_binary`, `pure = "on"`), `<name>_layer` (tar.bzl, `mutate(strip_prefix = "<pkg>/<name>_", package_dir = "app")` → binary ở `/app/<name>`), `<name>_image` (`oci_image` trên `@distroless_static`), `<name>_docker` (`oci_load`, tag `com.tm.go.<name>:v1.0.0`), và `<name>_push` chỉ khi có `repository`. Base `gcr.io/distroless/static-debian12:nonroot` pin bằng digest của **image index**, khai báo `linux/amd64` + `linux/arm64/v8` → rules_oci chọn manifest theo `--platforms`. Pure Go (`--@rules_go//go/config:pure`) cho binary tĩnh, chạy được trên `static` (không libc). Tên target tách thành hàm thuần `image_names`/`image_tag` để unit test bằng skylib `unittest`.
- **Bẫy / lưu ý**:
  - `go_binary` xuất file tại `<pkg>/<name>_/<name>`, không phải `<pkg>/<name>` — `strip_prefix` phải có hậu tố `_`.
  - `bazel build //...` trên macOS sẽ cố build image cho darwin (không có base darwin) → fail. Đặt `target_compatible_with = ["@platforms//os:linux"]` cho layer/image/load/push: build thường thì SKIPPED, `--config=linux-*` thì build. Không đổi platform mặc định sang Linux vì `go_test` phải chạy trên host.
  - Kiểm image thật sự distroless: `docker run --entrypoint /bin/sh ...` phải lỗi `stat /bin/sh: no such file or directory` (exit 127).
- **Code**: [tools/rules/com_tm_container.bzl#L26-L48 — image_names, image_tag](../../../../server/tools/rules/com_tm_container.bzl#L26-L48), [tools/rules/com_tm_container.bzl#L50-L112 — com_tm_go_image](../../../../server/tools/rules/com_tm_container.bzl#L50-L112), [MODULE.bazel#L24-L37 — oci.pull distroless](../../../../server/MODULE.bazel#L24-L37), [tools/rules/com_tm_container_test.bzl — unit test macro](../../../../server/tools/rules/com_tm_container_test.bzl)
- **Tham khảo**: [rules_oci — Go example](https://github.com/bazel-contrib/rules_oci/blob/main/docs/go.md), [distroless](https://github.com/GoogleContainerTools/distroless)

## Cross-build Linux trên macOS: `oci_load` dùng tar của platform **đích**
- **Chủ đề**: `bazel/toolchain`, `bazel/platforms`
- **Bối cảnh**: `bazel run --config=linux-arm64 //tools/smoke:smoke_docker` build xong nhưng script nạp image lỗi `.../bsd_tar_toolchains_linux_arm64/tar: cannot execute binary file` → Docker nhận rác (`unrecognized image format`), vậy mà **lệnh `bazel run` vẫn exit 0**.
- **Cách làm & lý do**: `oci_load` lấy tar cho script `bazel run` qua toolchain type `@tar.bzl//tar/toolchain:target_type`, được resolve theo platform đích (Linux). Nhưng `bazel run` luôn chạy trên máy exec. Đăng ký 4 toolchain riêng (`tools/rules/BUILD.bazel`): `target_compatible_with = linux`, `exec_compatible_with = <os/cpu của exec>`, trỏ tới bsdtar của chính exec platform; `register_toolchains("//tools/rules:all")` ở root module được ưu tiên hơn toolchain của tar.bzl. Phương án bị loại: transition image sang Linux và giữ `oci_load` ở host — cần 2 transition tự viết và mất thông tin arch khi quay về host; và bỏ `--platforms` khỏi `--config` — thì `bazel build --config=linux-amd64 //tools/smoke:smoke` không còn ra ELF x86-64.
- **Bẫy / lưu ý**: Luôn kiểm kết quả thật (`docker image ls`, `docker run`), không tin exit code của `bazel run`. `bazel cquery --config=linux-amd64 --output=files` trả đường dẫn trong `darwin_arm64-fastbuild` (tên output dir theo host) nhưng `file` báo `ELF 64-bit LSB executable, x86-64, statically linked` — đúng.
- **Code**: [tools/rules/BUILD.bazel#L7-L31 — bsdtar_run_on_*](../../../../server/tools/rules/BUILD.bazel#L7-L31), [MODULE.bazel#L39-L50 — use_repo tar toolchains + register_toolchains](../../../../server/MODULE.bazel#L39-L50), [.bazelrc#L12-L16 — build:linux-arm64 / linux-amd64](../../../../server/.bazelrc#L12-L16), [BUILD.bazel#L8-L23 — platform linux_amd64 / linux_arm64](../../../../server/BUILD.bazel#L8-L23)
- **Tham khảo**: [Bazel toolchain resolution](https://bazel.build/extending/toolchains#toolchain-resolution), [Platforms](https://bazel.build/extending/platforms)

## Binary mẫu tách `run(io.Writer)` khỏi `main`
- **Chủ đề**: `go/testing`
- **Bối cảnh**: `tools/smoke` là target mẫu cho mọi kiểm chứng build/image, nhưng vẫn phải có unit test thật (table-driven) cho cả nhánh lỗi.
- **Cách làm & lý do**: `main` chỉ gọi `run(os.Stdout)`; `run` nhận `io.Writer` nên test đưa `strings.Builder` (kiểm output đúng một dòng) và `failWriter` luôn trả lỗi (kiểm lỗi được trả về, so bằng `errors.Is`). `message` là hàm thuần, test biên chuỗi rỗng / toàn khoảng trắng.
- **Bẫy / lưu ý**: `errors.Is(err, nil)` chỉ true khi `err == nil` — dùng được làm "không mong lỗi" trong bảng test.
- **Code**: [tools/smoke/main.go#L15-L34 — message, run, main](../../../../server/tools/smoke/main.go#L15-L34), [tools/smoke/smoke_test.go — TestMessage, TestRun](../../../../server/tools/smoke/smoke_test.go)
