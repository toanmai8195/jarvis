# Test cases — P0-T07: Skeleton `com/tm/server/services/core`: config (env), slog JSON, chi router, pgxpool, `/healthz`, `/readyz`, `/metrics`

> **Phạm vi**: binary `services/core/cmd/server` chạy được bằng cả `go` lẫn Bazel. Binary đọc cấu hình từ biến môi trường, ghi log JSON bằng `log/slog`, định tuyến bằng `chi`, giữ một `pgxpool.Pool` tới PG core, và phục vụ `GET /healthz`, `GET /readyz`, `GET /metrics`. Prometheus local scrape được `/metrics`. Căn cứ:
> - Phase 0 README: dòng P0-T07. **P0-FR3** "`core` … có `/healthz` (sống) và `/readyz` (kết nối được DB)". **P0-NFR1** "Log dạng JSON". Challenge **G14** "Code build được bằng cả `go` và Bazel; CI chỉ test target bị ảnh hưởng". Challenge **G10** "slog JSON, Prometheus metrics".
> - [api.md](../../../../api.md) Internal API: `GET /healthz`, `/readyz` (Health check), `GET /metrics` (Prometheus). [architecture](../../../../architecture.md): core dùng "Go, PostgreSQL, pgx, sqlc, goose, chi". Prometheus "scrape … `/metrics` của service (từ P0-T07)".
> - [project-structure](../../../../project-structure.md): cây `services/core/cmd/server/main.go` ("wiring thủ công"), `internal/`, `internal/httpx/` (router, middleware). Mục "Go cho người từ Java" và "quy tắc 3 tầng" (health handler, parse config thì **copy**, không đưa vào `pkg/`). Bảng Bazel: 1 thư mục = 1 `go_library` do Gazelle sinh, test cần Docker gắn `tags = ["requires-docker", "requires-network"]` và `size = "large"`.
> - [local-setup](../../../../local-setup.md): biến `CORE_DATABASE_URL` = `postgres://snaptix:snaptix@localhost:5432/core`, cổng core **8080**, "Sao chép `.env.example` thành `.env` ở mỗi app/service".
> - [execute-all-notes](../../../execute-all-notes.md) mục P0-T02: "P0-T07+: target scrape của core thêm vào `deploy/observability/prometheus/prometheus.yml` (từ container gọi host qua `host.docker.internal:8080`; trên Linux cần `extra_hosts: host.docker.internal:host-gateway` cho service `prometheus`)". Mục P0-T01a: Gazelle đặt tên binary theo thư mục, nên `cmd/server` sinh target `//services/core/cmd/server:server`.

> **Giả định** (reviewer xem kỹ):
> - A1. **Biến môi trường**. Docs chỉ nêu `CORE_DATABASE_URL`, phần còn lại là giả định:
>
>   | Biến | Bắt buộc | Mặc định | Hợp lệ |
>   |---|---|---|---|
>   | `CORE_DATABASE_URL` | **có** (rỗng coi như thiếu) | — | DSN mà `pgxpool.ParseConfig` chấp nhận |
>   | `CORE_HTTP_ADDR` | không | `:8080` (mọi interface, để Prometheus trong container gọi qua `host.docker.internal`) | `host:port` |
>   | `CORE_LOG_LEVEL` | không | `info` | `debug` \| `info` \| `warn` \| `error` (không phân biệt hoa thường) |
>
>   Người làm có thể thêm biến (vd timeout ping) nếu có mặc định và được liệt kê trong `.env.example`. Tên khác bảng trên thì phải sửa lại TC và xin duyệt lại.
> - A2. **Lỗi cấu hình**: thiếu biến bắt buộc hoặc giá trị sai định dạng thì process thoát mã ≠ 0 trong ≤ 5 s. Thông báo là log JSON slog mức `ERROR` (cùng định dạng với log thường, TC13), phải **nêu tên biến** và **không** in mật khẩu của DSN. Không mở cổng HTTP.
> - A3. **Khởi động không phụ thuộc PG**: `pgxpool` tạo pool lười (không `Ping` bắt buộc lúc khởi động). PG chưa lên thì process vẫn chạy, `/healthz` 200, `/readyz` 503. PG lên thì `/readyz` tự về 200 mà không cần khởi động lại. Lý do: ngữ nghĩa liveness/readiness của P0-FR3, và P0-AT03 đòi hồi phục.
> - A4. **`/readyz`** ping PG với timeout riêng ≤ 2 s (context có deadline), nên trả trong ≤ 3 s kể cả khi PG treo mạng (`docker compose pause`). Body lỗi không lộ DSN/mật khẩu. **`/healthz`** không chạm DB, trả 200 trong < 0.5 s. Body của cả hai do người làm chọn (vd `{"status":"ok"}`). TC chỉ kiểm mã trạng thái và việc không lộ bí mật.
> - A5. **`/metrics`** dùng `prometheus/client_golang` (`promhttp`) với collector Go/process mặc định, nên có `go_goroutines`. Metric RED `http_server_request_duration_seconds_*` của dashboard P0-T06 **không** thuộc task này (middleware OTel HTTP là P0-T08, OTel SDK là P0-T10).
> - A6. **Prometheus scrape**: `prometheus.yml` thêm `job_name: core`, target `host.docker.internal:8080`. Service `prometheus` trong compose thêm `extra_hosts: ["host.docker.internal:host-gateway"]`. Image prometheus COPY cấu hình (`pull_policy: build`), nên phải build lại khi `up`.
> - A7. **Cấu trúc package** (gợi ý, không bắt buộc tên): `cmd/server/main.go` chỉ wiring. Config, router + handler health nằm trong `services/core/internal/...` (vd `internal/config`, `internal/httpx`). Pool có thể ở `internal/` hoặc `pkg/postgres` (docs có `pkg/postgres`). Không có thư mục `service/`, `repository/`, `controller/`, `model/`, `utils/`, `common/`, `helpers/`, `shared/`. Không `IFoo`/`FooImpl`. Không DI framework. `/readyz` phụ thuộc interface nhỏ khai báo ở phía dùng (vd `pinger { Ping(ctx) error }`), nhờ đó unit test không cần DB.
> - A8. **Integration test với PG thật** (testcontainers) thuộc khung **P0-T16**. Task này kiểm PG thật bằng curl + `docker compose stop/pause` (TC17–TC21). Nếu người làm vẫn viết test testcontainers thì test đó phải gắn tag Bazel đúng (TC06). `go test ./...` phải pass **khi không có Docker** (A4 của P0-T05: `make test` không cần stack).
>
> **Không thuộc task này**: middleware request ID / recover / access log / OTel HTTP và log có `trace_id`, `request_id` (P0-T08, P0-AT06). Graceful shutdown SIGTERM, `http.Server.Shutdown`, thứ tự đóng pool (P0-T09, P0-AT08..AT10). OTel SDK, export OTLP, trace (P0-T10). Image OCI cho `cmd/server`, `cmd/worker` (P0-T10a). `cmd/worker`.
